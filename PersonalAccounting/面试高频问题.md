# 个人记账 App 面试准备指南

## 一、项目经历（用于面试开场介绍）

### **个人记账 App (Personal Accounting)**

#### **项目描述**

这是一个为 Android 平台开发的个人记账应用，旨在帮助用户轻松记录和管理日常的收入与支出。用户可以添加、编辑和删除每一笔账单，并通过日历和统计图表清晰地了解自己的消费习惯和财务状况。该项目旨在提供一个简洁、直观的用户界面和流畅的操作体验。

#### **我的职责**

作为该项目的**独立开发者**，我负责了从零到一的整个开发过程，包括：

1.  **架构设计**：采用 MVC 模式组织代码，分离数据、视图和业务逻辑。
2.  **功能实现**：开发了包括账单管理、数据统计、日历视图在内的所有核心功能。
3.  **UI/UX 设计与实现**：使用 Material Design 组件构建了美观且用户友好的界面。
4.  **数据库管理**：设计并实现了本地 SQLite 数据库方案，用于持久化存储用户数据。

#### **技术栈**

*   **UI**: Android SDK, XML, Material Components, ConstraintLayout, RecyclerView
*   **架构**: MVC (Model-View-Controller)
*   **数据存储**: SQLite (`SQLiteOpenHelper`)
*   **开发语言**: Java

#### **项目亮点、挑战与我的思考**

在开发这个项目的过程中，我不仅学习了 Android 开发的基础，还遇到并解决了一些挑战，这让我对移动应用开发有了更深的理解。

**1. 挑战与思考：从混乱到有序的架构演进**

*   **遇到的问题**: 在项目初期，我将所有的数据库操作和业务逻辑都写在了 `Activity` 中。很快我发现，`Activity` 的代码变得异常臃肿和混乱，逻辑耦合严重，导致修复一个 bug 可能会引发新的问题，同时也非常难以进行单元测试。

*   **我的解决方案与思考**: 我意识到这种做法是不可持续的。通过学习，我了解到了 MVC 架构模式，并决定对项目进行重构。
    *   我创建了 `model` 包，将数据模型（`Bill.java`）和数据访问逻辑（`BillRepository.java`、`BillDbHelper.java`）封装起来。`BillRepository` 作为唯一的数据出口，所有对数据库的操作都必须通过它，这使得数据管理变得集中和清晰。
    *   `Activity` 和 `Fragment` 作为 `Controller`，只负责处理用户的交互、调用 `Repository` 获取数据，并将数据交给 `View` 进行展示。
    *   这次重构让我深刻体会到**“关注点分离”**的重要性。一个好的架构不仅能让代码更易于维护和扩展，还能提高开发效率。

**2. 挑战与思考：优化用户体验，避免界面卡顿**

*   **遇到的问题**: 当账单记录越来越多时，我发现在进入主页或者查询账单时，应用界面会出现短暂的卡顿（UI Freeze）。通过学习和调试，我定位到问题的原因是：我在主线程（UI 线程）中执行了耗时的数据库查询操作。

*   **我的解决方案与思考**: 为了解决这个问题，我学习并实践了 Android 的多线程编程。
    *   我将所有数据库的读写操作都放到了后台线程中执行。例如，在查询账单列表时，我可以使用 `AsyncTask` 或者创建一个 `Executor` 线程池来执行查询任务。
    *   当后台线程完成数据查询后，再通过 `Handler` 或者 `runOnUiThread()` 将结果切换回主线程，并更新 `RecyclerView` 的数据。
    *   这个改进虽然代码量不大，但效果显著，应用变得流畅了许多。这让我明白了**保证主线程流畅是提升用户体验的关键**，任何耗时操作（如网络请求、数据库读写、复杂计算）都必须在后台线程执行。

**3. 挑战与思考：打造直观易用的 UI**

*   **遇到的问题**: 我希望应用的界面不仅仅是能用，而且要好看、好用。例如，如何让用户在日历上直观地看到当天的消费情况？如何让收入和支出在列表中有明显的区分？

*   **我的解决方案与思考**:
    *   我利用 `Material Components` 库，设计了统一的视觉风格，并为不同的按钮状态（如按下、禁用）创建了 `selector` 资源，提升了交互的细节体验。
    *   在账单列表（`RecyclerView`）中，我通过在 `Adapter` 中判断账单类型（收入或支出），为不同的类型设置不同的图标和颜色，让用户一目了然。
    *   对于日历视图，我通过自定义 `DateSelectorView`，在绘制日期时，查询数据库中该日期是否有账单记录，如果有，则在日期下方绘制一个小圆点作为标记。这让用户可以快速定位到有消费记录的日期。
    *   通过这些 UI 上的细节打磨，我学会了如何站在用户的角度思考问题，并通过细节设计来提升产品的整体体验。

## 二、面试高频问题

对于个人记账这个项目，面试官的提问会主要围绕以下几个方面展开，目的是考察你的 **Android 基础知识、架构设计能力、解决问题的思路以及你的技术思考深度**。

### 1. 宏观架构与设计思路

这类问题用于开场，考察你对项目的整体把握和设计思考。

#### “能简单介绍一下你的项目吗？你为什么选择 MVC 架构？”
*   **面试官想考察什么**：你的沟通表达能力，以及对项目最基本架构的理解。你是否清楚 MVC 各部分的职责？你是否知道它的优缺点？
*   **准备思路**：回顾项目描述。解释 MVC 如何帮助你分离业务逻辑（Controller）、数据处理（Model）和界面展示（View），让代码结构更清晰。可以诚实地表示，在项目初期，MVC 是一个非常适合初学者上手且易于理解的模式。

#### “在这个项目中，你觉得最有挑战性的部分是什么？你是如何解决的？”
*   **面试官想考察什么**：这是**必考题**，也是你展示亮点的最佳机会！面试官想看到你解决问题的能力、学习能力和思考过程，而不仅仅是代码的堆砌。
*   **准备思路**：从之前为你准备的“项目亮点、挑战与我的思考”中选择 1-2 个你最有感触的点。比如“主线程卡顿”或“代码结构混乱”，详细地讲述你**发现问题 -> 分析原因 -> 寻找方案 -> 解决问题 -> 总结反思**的完整过程。

#### “如果让你重新做这个项目，你会在哪些方面进行改进？”
*   **面试官想考察什么**：你的反思能力和技术视野。你是否满足于现状？你是否了解更先进的技术或更好的实现方式？
*   **准备思路**：这是一个加分项。你可以从以下几点来回答：
    *   **架构升级**：提到 MVC 的不足（比如 `Activity/Fragment` 过于臃肿），并表示会考虑使用 **MVVM** 架构，并引入 `ViewModel` 和 `LiveData` (或 `Flow`) 来更好地管理 UI 相关的数据和生命周期，实现数据驱动的 UI 更新。
    *   **语言升级**：会考虑使用 **Kotlin** 来代替 Java，因为 Kotlin 语言特性（如空安全、协程、扩展函数）能让代码更简洁、更安全。
    *   **数据库优化**：原生的 `SQLiteOpenHelper` 写起来比较繁琐，可以考虑使用 **Room** 框架，它能以注解的方式简化数据库操作，并在编译期检查 SQL 语句的正确性。

### 2. Android 核心基础

这类问题考察你对 Android 开发基础知识的掌握是否扎实。

#### “项目中用到了 `RecyclerView`，它和 `ListView` 有什么区别？`ViewHolder` 的作用是什么？”
*   **面试官想考察什么**：列表控件是 Android 开发的核心，这个问题考察你对 `RecyclerView` 工作原理的理解。
*   **准备思路**：`RecyclerView` 的核心优势在于它的**回收复用机制**。`ViewHolder` 缓存了 `itemView` 的组件引用（`findViewById`），避免了重复查找；`Recycler` 回收池则可以复用那些滑出屏幕的 `itemView`，极大地提升了列表滑动的性能。

#### “你是如何处理耗时操作的，比如数据库查询？为什么不能在主线程（UI 线程）做这些事？”
*   **面试官想考察什么**：对 Android 线程模型的理解，这是保证 App 流畅的关键。
*   **准备思路**：解释在主线程进行耗时操作会导致 ANR (Application Not Responding)。然后可以举例说明你使用了 `AsyncTask` 或 `Executors` 线程池将数据库读写放到了后台。可以进一步说明 `AsyncTask` 的缺点（如内存泄漏），并表示现在更推荐使用 Kotlin 协程等更现代的异步方案。

#### “`Activity` 和 `Fragment` 的生命周期是怎样的？你在项目中是如何使用它们的？”
*   **面试官想考察什么**：对 Android 应用最核心组件生命周期的理解。
*   **准备思路**：能够画出或清晰描述 `Activity` 的生命周期图（`onCreate` -> `onStart` -> `onResume` -> `onPause` -> `onStop` -> `onDestroy`）。并能解释在屏幕旋转或内存不足时，生命周期的变化。可以结合项目中的 `BillEditActivity` 举例，比如在 `onPause` 时可以保存用户未提交的草稿数据。

### 3. 数据库与数据存储

这类问题考察你对数据持久化的理解。

#### “你是如何设计数据库表的？如果未来需要增加一个新的字段（比如‘备注’），你应该怎么做？”
*   **面试官想考察什么**：数据库设计能力和版本管理能力。
*   **准备思路**：描述你的 `Bill` 表包含哪些字段（ID, 金额, 类型, 分类, 日期等）。对于增加字段，你需要解释会修改 `Bill` 数据模型，然后在 `BillDbHelper` 的 `onUpgrade()` 方法中，通过执行 `ALTER TABLE` SQL 语句来为旧的数据库表添加新列，并记得增加数据库的版本号。

#### “你提到了 `BillRepository` 这个类，它在你的项目中扮演了什么角色？”
*   **面试官想考察什么**：对“仓库模式”（Repository Pattern）的理解，这是现代 Android 架构中的一个重要概念。
*   **准备思路**：解释 `Repository` 的作用是作为**统一的数据来源**。它对上层（Controller/ViewModel）屏蔽了数据的具体来源（是来自本地数据库，还是未来可能增加的网络 API）。这样做的好处是：1. 业务逻辑代码更清晰，不需要关心数据到底从哪来；2. 便于进行单元测试，可以模拟一个 `FakeRepository` 来测试业务逻辑；3. 未来扩展更容易，比如增加网络同步功能时，只需修改 `Repository` 内部的逻辑即可。
